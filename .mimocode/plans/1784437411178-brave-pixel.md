## 一、顶层架构审视

### 1.1 架构总评：8.5/10

项目采用 `presentation → domain ← data` 4 层架构 + `core/` umbrella 共享层。整体设计**非常扎实**，domain 层纯净度极高。

| 维度 | 评分 | 说明 |
|------|------|------|
| 依赖方向 | 10/10 | domain 层 0 Flutter / 0 Drift / 0 data / 0 presentation 引用 |
| 跨 feature 耦合 | 10/10 | 非 hub feature 零互相引用 |
| 共享层健康度 | 10/10 | 5 个文件均被 2+ 层使用（19-99 行/文件） |
| Provider 模式 | 9/10 | domain 接口暴露、UseCase 编排、autoDispose 隐私隔离 |
| 路由设计 | 9/10 | 3 类 transition 按频度分类，Shell + NavigationRail 响应式 |
| 暗色模式 | 8/10 | 8 个 dynamic getter 已就位，但部分 widget 仍用静态 token |
| 国际化 | 7/10 | ARB 基础设施完善，但 ~230 处中文硬编码绕过 AppLocalizations |
| 测试覆盖 | 9/10 | 74 文件覆盖 domain/data/presentation 三层，命名规范 |

### 1.2 架构层边界违规

| # | 严重度 | 位置 | 问题 | 修复难度 |

| A1 | **🟡 中** | `core/routing/app_router.dart:8-21` | core/ 层 import 了 14 个 presentation/ 页面文件 + 1 个 provider 文件。core/ 本应是基础设施层，不应依赖 presentation/ | 中等 — 可将 app_router.dart 移至 presentation/ 或接受为 go_router 的架构 trade-off |
