## 什么是 mojibake

- **症状**: 中文 / 繁体 / 特殊符号 显示为 `鎮ㄨ鏂` `閬ユ捣` `充濂充`
  之类的乱码
- **根因**: 文件以 UTF-8 写入,但被工具(Windows Notepad / PowerShell
  5.1 / git 旧 config)以 GBK / CP936 / Big5 重新解码,再以 UTF-8 写回
- **典型场景**:
  1. 在 Windows 资源管理器双击 `.dart` / `.arb` 用 Notepad 打开 → 保存时
     自动转 ANSI (GBK) → 重新以 UTF-8 读 → 全乱
  2. PowerShell `Get-Content | Set-Content` 走默认 ANSI codepage → 静默坏
  3. git 没设 `core.autocrlf=false`,跨平台 commit 时 CRLF/LF 转换吃中文
  4. OpenCC s2tw 繁化工具把 zh-Hant 的"麽→么"之类字改了 → 跟 GBK mojibake
     巧合撞形

## 修真方法论 (标准 SOP)

### Step 1: 识别 mojibake

```bash
# 1) grep 找可疑字符 (常见 mojibake 标志字符)
grep -P '[\xE4-\xE9][\x80-\xBF]{2}' lib/**/*.dart | head

# 2) 看 PR diff 是不是有大量 "闊充" "闆" "閬ユ捣" 之类
git diff main | grep -P "[\xE4-\xE9][\x80-\xBF]"

# 3) check_no_pua.py 脚本 (v0.22 round 31 修真后加的守护)
python scripts/check_no_pua.py
```

### Step 2: 找原文

```bash
# 1) 看 git blame,找 mojibake 是哪个 commit 引入的
git log -p --all -S "<mojibake 字符>" -- lib/path/to/file.dart

# 2) 看上一个干净 commit 的内容
git show <clean_commit>:lib/path/to/file.dart | head
```

### Step 3: 用 Read/Edit 工具修真 (绝不 shell pipeline)

```python
# BAD — PowerShell 默认 ANSI codepage,会重新 mojibake
Get-Content lib/main.dart | %{ $_ -replace "xxx", "yyy" } | Set-Content lib/main.dart

# GOOD — Read 工具读 → Edit 工具写,完全 UTF-8 round-trip
# 1. Read lib/main.dart (整文件,UTF-8)
# 2. Edit 工具 old_string="<mojibake>" new_string="<正确中文>"
```

### Step 4: 守护脚本 (PR-time gate)

- `python scripts/check_no_pua.py` — 检查 PUA 字符 (mojibake 常用 0xE000-0xF8FF)
- `python scripts/check_arb_keys.py --staged` — ARB key 同步 (zh/zh-Hant/en)
- `dart scripts/check_all.dart` — 4 层架构 purity + consistency

### Step 5: PR review

- 看 diff 是不是有大量 "充閬ユ捣鑱旂郴" 之类
- 看 commit msg 是不是带 "mojibake" "修真" "encoding" 关键字
- 如果有,触发修真 SOP
